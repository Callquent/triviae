Ajouter une application

Guide pour installer vos applications Next.js dans « Triviae » : importer un .zip, régler l'application, comprendre ce qui est automatique.

1. Le principe

Chaque application vit sous son propre préfixe : http://<adresse-du-pc>:8080/apps/<identifiant>. L'identifiant s'écrit en minuscules, chiffres et tirets (par exemple budget ou recettes).

Les applications tournent sur le PC ; le téléphone, sur le même Wi-Fi, s'y connecte avec le QR code de l'accueil. Les applications se gèrent depuis le PC (la gestion n'est pas accessible depuis le téléphone).

2. Importer un .zip (méthode simple)

  1. Ouvrez « Ajouter une application » depuis le PC : l'onglet Applications, bouton « + Ajouter une application » ou la tuile « + ». Déposez le .zip de votre projet.
  2. Vérifiez le nom, la description et l'identifiant (l'adresse sera /apps/<identifiant>), puis touchez « Compiler et installer » (ou « Installer » pour un projet déjà compilé).
  3. Patientez : la progression se fait par phases (préparation, dépendances, compilation, démarrage). Vous pouvez quitter la page et revenir, le suivi reprend. Puis « Ouvrir ».

La tuile apparaît sur l'accueil et l'application démarre. Le menu ⋯ de la tuile donne le journal, le redémarrage et les réglages. Importer une application dont l'identifiant existe déjà la remplace (mise à jour) ; ses données sont conservées.

3. Les trois sortes de .zip

Contenu du .zipCe qui se passe
Projet source Next.js
package.json, sans node_modules ni .next		Compilé sur ce PC. Il faut une connexion Internet : la première fois, l'outil npm puis les dépendances sont téléchargés (quelques minutes, plus rapide ensuite). Le préfixe /apps/<identifiant>, la sortie autonome et l'ignorance des erreurs de type sont ajoutés automatiquement : inutile de modifier next.config. La progression est affichée, on peut annuler ; en cas d'échec, les dernières lignes du journal sont montrées.

Projet déjà compilé

Une application qui utilise des modules natifs (Prisma, better-sqlite3, sharp…) doit être compilée sur le système où elle tournera : une compilation faite sous Windows ne fonctionnera pas sous Ubuntu, et inversement. Importez le .zip source sur chaque machine plutôt qu'un projet compilé ailleurs.

4. Le fichier app.json

La plateforme l'écrit à l'import, dans apps/<identifiant>/app.json. Vous pouvez l'ouvrir pour le modifier (puis redémarrer l'application).

ChampRôle
nameNom affiché sur la tuile.
descriptionPhrase sous le nom.
iconLogo de la tuile, relatif au dossier public/ (ex. "/icon-192.png"). Écrit automatiquement quand un logo usuel est trouvé (voir 5).
actionsBoutons de la tuile : [{ "label": "Ouvrir", "path": "/" }, { "label": "Scanner", "path": "/scan" }]
storage"pc" ou "off" : données du navigateur gardées sur le PC (voir 5). Par défaut, détecté automatiquement.
syncSynchronisation entre deux PC (voir 8).
basePath, entryGérés par la plateforme (/apps/<identifiant> et server.js) : à ne pas changer.

La version affichée sur l'accueil est celle du package.json du projet (champ "version").

5. Ce que fait la plateforme pour vous

Logo

Le logo est cherché dans public/ : icon-192.png, icon-512.png, icon.png, icon.svg, apple-touch-icon.png, logo.png, favicon.png / .svg / .ico (dans cet ordre) et son chemin est inscrit dans app.json. Pour un autre fichier : "icon": "/mon-logo.png". Sans logo, la tuile montre l'initiale de l'application.

Appels fetch("/api/…")

Les applications vivent sous /apps/<identifiant>. Le préfixe est ajouté automatiquement aux appels fetch et XMLHttpRequest vers « /… » : une application qui écrit fetch("/api/produits") fonctionne sans modification.

Prisma + SQLite

  • La base est créée dans le dossier de données (fichier base.db), jamais dans l'application.
  • À chaque démarrage, les tables et colonnes manquantes sont créées d'après prisma/schema.prisma. Rien n'est supprimé : vos données restent quand vous ajoutez des champs.
  • DATABASE_URL est fournie automatiquement.
  • Seul SQLite est pris en charge (pas PostgreSQL ni MySQL). Les messages « [base de données] … » apparaissent dans le journal.

Données sur le PC (applications qui gardent tout dans le navigateur)

Une application qui range ses données dans le localStorage est reconnue automatiquement. Le PC garde alors la copie de référence : chaque modification faite sur le téléphone ou le PC lui est envoyée aussitôt, et chaque appareil reçoit les données du PC à l'ouverture. Les listes d'éléments (objets avec un champ id) sont fusionnées élément par élément ; sinon la modification la plus récente l'emporte. Hors connexion, un témoin « En attente d'envoi au PC » s'affiche et l'envoi reprend au retour du Wi-Fi. Réglage : Réglages, « Données sur le PC », ou "storage" dans app.json.

Liens entre applications (onglet « Liens »)

L'onglet Liens de Triviae montre quelles applications échangent des données entre elles : un schéma en étoile (les pointillés en mouvement vont de l'application qui fournit vers celle qui reçoit) et, pour chaque application, ce qu'elle reçoit et ce qu'elle envoie. Une application déclare ses liens de deux façons :

  • Liens fixes, dans app.json : "links": [{ "app": "plantes", "label": "Arrosages", "direction": "in" }]
  • Liens choisis par l'utilisateur (ex. l'agenda), par une route GET /api/liens qui répond { "links": [{ "app": "plantes", "label": "Arrosages", "direction": "in" }] }.

direction : "in" (défaut) = l'application reçoit des données de l'autre, "out" = elle lui en envoie, "both" = dans les deux sens. app est l'identifiant de l'autre application ; pour un site extérieur, écrivez "name": "Nom" à la place. L'application doit être démarrée ; arrêtée, ses derniers liens connus restent affichés. Un lien vers une application non installée est signalé en rouge.

Retour à « Triviae »

Dans chaque application, un petit onglet bleu au bord de l'écran ramène à la liste (il se déplie au survol). On peut le faire glisser en hauteur ou de l'autre côté de l'écran ; sa position est mémorisée.

Où écrire les données de l'application

Une application qui enregistre des fichiers (JSON, images envoyées…) doit écrire dans process.env.DATA_DIR (fourni par la plateforme), pas dans son dossier :

const DATA_DIR = process.env.DATA_DIR ?? path.join(process.cwd(), "data");

Pour les adresses écrites à la main (<img src="/…">), ajoutez le préfixe : (process.env.NEXT_PUBLIC_BASE_PATH ?? "") + chemin. Les <Link>, redirect() et le routeur le font tout seuls.

6. Préparer le projet à la main (avancé)

Utile pour compiler vous-même ou installer sans passer par l'import.

  1. Dans le projet (une fois), dans next.config.ts : 
    const basePath = process.env.BASE_PATH ?? "";
const nextConfig = {
  ...(basePath ? { basePath } : {}),
  ...(process.env.STANDALONE ? { output: "standalone" } : {}),
  env: { NEXT_PUBLIC_BASE_PATH: basePath },
};
  2. Compiler sur le système qui fera tourner l'application. 
    Windows (PowerShell) : $env:BASE_PATH="/apps/budget"; $env:STANDALONE="1"; npx next build
Ubuntu               : BASE_PATH=/apps/budget STANDALONE=1 npx next build
  3. Préparer le dossier (Node.js installé pour cette étape) : 
    node outils/preparer-application.mjs /chemin/du/projet budget --nom "Mon budget" --description "Suivi des dépenses"
    Cela crée apps/budget, avec son app.json (logo détecté).
  4. Accueil : « Ou copier le dossier à la main », puis « Chercher de nouvelles applications ». La tuile apparaît ; le téléphone la voit au prochain rechargement.

7. Utiliser sans le PC (téléphone)

Sur le téléphone, ouvrez Triviae puis « Copie sur le téléphone ».

  1. Installez une fois le certificat du PC (bouton « Télécharger le certificat », puis réglages Android : Sécurité, Chiffrement et identifiants, Installer un certificat, Certificat d'autorité).
  2. Ouvrez la version sécurisée (https, même adresse et même port) et touchez « Enregistrer la copie ».

Hors ligne, le téléphone sert les pages déjà ouvertes ou enregistrées. Les données « sur le PC » restent utilisables et repartent vers le PC au retour du Wi-Fi ; les données d'une base (Prisma/SQLite) sont en lecture seule (dernière version consultée).

Envoyer des données au PC depuis le téléphone. Une route API reçoit les fichiers ; une file d'attente sur le téléphone garde l'envoi tant que le PC est injoignable ; un identifiant unique par élément évite les doublons. En http simple, évitez crypto.randomUUID() et les service workers : ils exigent un contexte sécurisé.

8. Synchronisation entre deux PC (facultatif)

Une application peut participer à la synchronisation Windows / Ubuntu. Dans son app.json : "sync": { "path": "/api/sync" }, et l'application expose sous ce chemin trois routes que seul le hub peut appeler :

GET  <path>/state       toutes les données, suppressions comprises (JSON)
POST <path>/merge       reçoit l'état de l'autre PC, le fusionne,
                        renvoie { state, needFiles: [fichiers manquants] }
GET  <path>/file/<nom>  un fichier (photo…)     PUT : reçoit un fichier
  • Le hub ajoute l'en-tête x-sync-token (variable SYNC_TOKEN fournie à l'application) : l'application refuse toute requête sans lui et revalide les données reçues champ par champ.
  • Chaque enregistrement a un identifiant et une date updatedAt ; une suppression laisse un « tombeau » (deletedAt) ; la fusion est symétrique (A puis B donne le même résultat que B puis A).

9. En cas de problème

SymptômeÀ faire
L'application ne démarre pas ou affiche une erreurMenu ⋯ de la tuile (ou Réglages), « Journal » : il montre ce que l'application a écrit. Elle est relancée automatiquement si elle s'arrête ; « Redémarrer » force un nouveau démarrage.
Erreur 500 avec PrismaOuvrez le journal. Une ligne « [réparation] module externe… » est normale. Si l'erreur persiste, envoyez les premières lignes du journal.
Erreur « sharp » / ERR_DLOPEN_FAILED (images, Windows)L'optimisation d'images de Next.js (module natif « sharp ») ne se charge pas toujours. La plateforme sert maintenant les images telles quelles (images.unoptimized) : réimportez le .zip source de l'application pour appliquer ce réglage.
La compilation échoueLes dernières lignes du journal de compilation sont affichées à l'import. Vérifiez la connexion Internet et que le projet compile chez vous avec npx next build.
Le logo n'apparaît pasVérifiez que le fichier est dans public/ (ex. public/icon-192.png) ou indiquez "icon" dans app.json.
L'onglet bleu « Triviae » manqueRechargez la page (Ctrl+F5) et vérifiez que Triviae est à jour puis redémarré.
Une image ou un appel ne trouve pas son adresseAjoutez le préfixe aux adresses écrites à la main (voir 5).
